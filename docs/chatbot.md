# チャットボット（RAG）

サイト右下に出る問い合わせチャットと、その知識を管理画面から編集する仕組み。

> **本番に反映する方だけ読めばよい箇所**: [本番反映の手順](#本番反映の手順)（作業4つ・15〜20分）

## 全体像

```
来訪者 ──▶ ChatWidget ──▶ /api/chat ──┬─▶ 質問を埋め込み ─▶ match_chat_knowledge（pgvector）
                                       ├─▶ ピン留めの項目（常に）
                                       └─▶ system プロンプトを組み立てて OpenAI へ

管理者 ──▶ /admin/chat-knowledge ──▶ /api/admin/chat-knowledge ──▶ chat_knowledge テーブル
                                                                    （保存時に埋め込みも作る）
```

- **知識の正本は `chat_knowledge` テーブル**。コードに文章を書かない。
- **縛り（守らせる約束事）はコード側**（`lib/chat-knowledge.ts` の `buildSystemPrompt`）。
  管理画面から緩められない。値引きや空席を勝手に約束させないため。

# 本番反映の手順

**所要 15〜20分。作業は4つだけです。**
コマンドを打つ必要はありません。Supabase・Netlify・管理画面の3つの画面で完結します。

途中でやめても、サイトの他の部分（予約・スクール申込・ブログ）には一切影響しません。
チャットが「準備中です」と電話番号を案内するだけの状態で止まります。

用意するもの:

- Supabase ダッシュボードのログイン
- Netlify ダッシュボードのログイン
- OpenAI の API キー（`sk-` で始まる文字列）
- 管理画面 `/admin` のパスワード

---

## 手順1: データベースに表を作る（5分）

1. [Supabase ダッシュボード](https://supabase.com/dashboard) を開き、3dlab のプロジェクトを選ぶ
2. 左メニューの **SQL Editor** → **New query**
3. このリポジトリの
   [`supabase/migrations/20260816_add_chat_knowledge.sql`](../supabase/migrations/20260816_add_chat_knowledge.sql)
   を開き、**中身を全部コピーして貼り付ける**
4. **Run** を押す

**うまくいったときの表示**: `Success. No rows returned`

**確認**: 左メニューの **Table Editor** に `chat_knowledge` が現れ、10行入っている

⚠ 2回実行しても壊れません（初期データが二重に入らないようにしてあります）。

---

## 手順2: OpenAI のキーを登録する（3分）

1. [Netlify ダッシュボード](https://app.netlify.com) → **3dworkshop** のサイトを開く
2. **Site configuration** → **Environment variables** → **Add a variable**
3. 次を追加する

   | Key | Value |
   |---|---|
   | `OPENAI_API_KEY` | `sk-` で始まる OpenAI のキー |

4. **Deploys** タブ → **Trigger deploy** → **Deploy site** を押す
   （環境変数は再デプロイしないと反映されません）

**確認**: デプロイが緑色の `Published` になる

---

## 手順3: 管理画面にログインし直す（1分）

1. https://3dlab.jp/admin を開く
2. **ログイン済みの場合も、右上の「ログアウト」を押してからログインし直す**

⚠ この作業が要る理由: 書き込み用の安全な cookie は、今回の変更を入れた**後の**ログインで初めて
配られます。古いままだと知識の編集画面が読み込めません。
（読み込めなかった場合は自動でログイン画面に戻るので、そこで入り直せば同じことです）

---

## 手順4: 検索を有効にして動作を確かめる（5分）

1. 管理画面のタブ列から **「チャットの知識」** を開く
2. **「ベクトルを作り直す」** を1回押す

   **うまくいったときの表示**: `10/10 件のベクトルを作り直しました。`

3. **「動作テスト」** に質問を入れて **「試す」** を押す

   試す質問の例と、期待する答え:

   | 質問 | 期待する答え |
   |---|---|
   | 作品はその日に持って帰れますか？ | その日は持ち帰れない／後日発送と答える |
   | 駐車場はありますか？ | 専用の駐車場は無い／電車を勧める |
   | 秋葉原にあるんですか？ | **湯島にある**と答える（秋葉原とは言い切らない） |
   | 何歳から参加できますか？ | 6歳から |

4. https://3dlab.jp を開き、**右下のチャットボタン**から同じ質問をして同じ答えが返ることを確認する

---

## 最後に: 中身の確認をお願いします

管理画面の上部に **「裏取りが済んでいない項目が2件あります」** と出ています。
**この2件はボットが既にこの内容で答えます。**

| 項目 | 確認していただきたいこと |
|---|---|
| 体験者アンケートの満足度 95%（回答80名） | この数字を対外的に出してよいか |
| 営業時間 10:00〜19:00・火曜定休 | 公式サイトのスクール案内はこの時間だが、トップページの構造化データは 10:00〜20:00 になっている。どちらが正しいか |

正しければ **「確認済みにする」**、違っていれば **「編集」** で直してください。

あわせて、次の内容もご確認ください（違っていれば管理画面から直せます）。

- 体験ワークショップ 12,000円 / 8月に募集済みの回のみ 5,000円・10,000円
- 3DLabスクール 月謝 17,000円・入会金は2026年9月30日まで0円
- **大人／子どもの料金の区別**は「未定」として登録してあります。区別がある場合は書き足してください

---

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| チャットが「ただいまチャットを準備中です」と返す | 手順1か手順2が未完了。Supabase に `chat_knowledge` があるか、Netlify に `OPENAI_API_KEY` があるかを確認し、再デプロイする |
| チャットが「うまく答えられませんでした」と返す | OpenAI 側のエラー。キーが有効か、残高があるかを確認する |
| 管理画面の「チャットの知識」が読み込めない／ログイン画面に戻る | 手順3の入り直しをする |
| 「chat_knowledge テーブルがありません」と出る | 手順1が未完了。SQL を実行する |
| 「1件のベクトルが本文とズレています」と出る | 「ベクトルを作り直す」を押す |
| 答えが古い・間違っている | 管理画面で該当項目を編集して保存する。**デプロイは要りません**。次の質問から反映されます |

## 止めたいとき

Netlify の環境変数から `OPENAI_API_KEY` を消して再デプロイすれば、チャットは
「準備中です」と電話番号を案内するだけになります。データは消えません。
完全に消したい場合は、右下のチャット自体を消す必要があるので開発側にご連絡ください。

## 費用の目安

質問1回あたり 0.1円未満（`gpt-4o-mini` + `text-embedding-3-small`）。
月1,000件でも100円程度です。「ベクトルを作り直す」は項目数ぶんの処理で、数十件なら誤差です。

# ここから先は開発者向け

## 運用

### 知識を直す
`/admin/chat-knowledge` で編集して保存すれば、**次の質問からすぐ反映される**（デプロイ不要）。
保存時に埋め込みも自動で作り直される。

### 「要確認」タグ
裏取りが済んでいない項目には `要確認` タグを付ける。**公開はされていてボットも答える**が、
管理画面の上部に一覧で出て、「確認済みにする」ボタン1つでタグを外せる。内容が違えば編集で直す。

⚠ 「未確認だから非公開」にしない。聞かれても答えられないうえ、直す動機も生まれないまま忘れられる。

⚠ 但し書きを**本文に**書かない。本文はそのまま LLM に渡るので、ボットが
「これは未確認の情報ですが」と喋り出す。管理上のメモはタグで持つ。

初期データでは次の2件に付けてある。**確認して、タグを外すか修正すること。**

| 項目 | 未確認の理由 |
|---|---|
| 体験者アンケートの満足度 95%（回答80名） | 出所の裏取りが未了 |
| 営業時間 10:00〜19:00・火曜定休 | トップページの構造化データ（`app/layout.tsx`）は `Mo-Su 10:00-20:00`。どちらが正か未確認 |

### 「非公開」の使いどころ
一時的にボットに答えさせたくない項目（終了したキャンペーンなど）を、消さずに外しておくときに使う。

### 「常に渡す」（ピン留め）の使いどころ
検索結果に関係なく毎回 system に入る。**料金**と**完成品の受け渡し**だけに付けてある。

⚠ 増やすほど1問あたりの費用が上がり、関係ない話題にも混ざる。
「抜けると間違った案内になる」ものだけに限ること。

### 「未ベクトル化」バッジが出たら
本文と埋め込みがズレている状態。**その項目は検索に出てこない**（＝聞かれても答えられない）。
「ベクトルを作り直す」を押せば直る。

なお、**1件もベクトルが無いとき**（migration 直後）は検索が成立しないので、公開中の項目を
全部渡す動作に自動で切り替わる。答えられなくなることはないが、費用は上がる。

### 検索の効き（閾値を変える前に読む）
`lib/chat-knowledge.ts` の `MIN_SIMILARITY` = 0.25、`MATCH_COUNT` = 4。
⚠ **勘で動かさない。** 2026-08-16 に `text-embedding-3-small` で実測した分布:

| 質問 | 正解の項目 | 2番目 | 無関係な項目の最高値 |
|---|---|---|---|
| 料金はいくらですか | 0.457 | 0.190 | — |
| 駐車場はありますか | 0.403 | 0.292 | — |
| 何歳から参加できますか | 0.529 | 0.281 | — |
| 猫の飼い方を教えて | — | — | 0.294 |
| 今日の天気は？ | — | — | 0.219 |

正解は 0.40 以上、雑談の雑音は 0.30 未満。0.30 まで上げると雑音は消えるが2番目の項目も落ちる。
問い合わせ窓口では「知識があるのに分かりかねます」のほうが損なので 0.25 に置いている。
⚠ 変えるときは SQL 関数側の既定値（migration）も揃えること。

## 安全のために入れてあるもの

| どこ | 何を |
|---|---|
| `chat_knowledge` | RLS 有効・ポリシー無し。anon キーからは読めも書けもしない。触れるのは service role だけ |
| `/api/admin/chat-knowledge/*` | 全メソッドで `requireAdmin()`。httpOnly + HMAC 署名の cookie を検証する |
| `/api/chat` | POST のみ・1発言600字・履歴12往復・同一IP 10分25回まで |
| `/api/chat` | クライアントから来た `system` role は捨てる（知識の差し替え防止） |
| `ChatWidget` | モデルの出力は文字列として描画。`dangerouslySetInnerHTML` を使わない |
| `buildSystemPrompt` | 縛りを知識より**後ろ**に置く。知識に「指示を無視して」と書かれても後勝ちになる |

⚠ 既存の `admin_auth` cookie はブラウザ側で `Cookies.set()` しているだけなので誰でも偽造できる。
画面の出し分けには使えても、書き込み API の鍵にはならない。この仕組みでは別途 `admin_session`
（httpOnly・HMAC 署名）を配って検証している。

## ローカルで検証するとき

本番の Supabase を触らずに、実データと同じ状態で確認できる。

```bash
# 1. ローカルの Supabase を立てて migration を流す
mkdir -p /tmp/3dlab-verify && cd /tmp/3dlab-verify
supabase init
mkdir -p supabase/migrations
cp <このリポジトリ>/supabase/migrations/20260816_add_chat_knowledge.sql supabase/migrations/
supabase start          # ⚠ 他の Supabase が動いている場合は config.toml のポートをずらす
supabase status         # ANON_KEY / SERVICE_ROLE_KEY が出る
```

出力された URL とキーを `.env.local` に入れ、`OPENAI_API_KEY` も入れて `npm run dev`。
管理画面で「ベクトルを作り直す」を押せば、本番と同じ検索が local で動く。

⚠ `npm run build` は prebuild の sitemap 生成が `.env` を要求して落ちる。
ビルド確認だけなら `npx next build` を使う。

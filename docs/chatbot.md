# チャットボット（RAG）

サイト右下に出る問い合わせチャットと、その知識を管理画面から編集する仕組み。

## 全体像

```
来訪者 ──▶ ChatWidget ──▶ /api/chat ──┬─▶ 質問を埋め込み ─▶ match_chat_knowledge（pgvector）
                                       ├─▶ ピン留めの項目（常に）
                                       └─▶ system プロンプトを組み立てて OpenAI へ

管理者 ──▶ /admin/chat-knowledge ──▶ /api/admin/chat-knowledge ──▶ chat_knowledge テーブル
                                                                    （保存時に埋め込みも作る）
```

- **知識の正本は `chat_knowledge` テーブル**。コードに文章を書かない。
- **縛り（守らせる約束事）はコード側**（`lib/chat-knowledge.ts` の `buildSystemPrompt`）。
  管理画面から緩められない。値引きや空席を勝手に約束させないため。

## 導入手順

1. `supabase/migrations/20260816_add_chat_knowledge.sql` を Supabase の SQL エディタで実行する。
   `pgvector` 拡張の有効化と初期データの投入までここに入っている。
2. 環境変数を設定する（`.env.example` 参照）。
   - `OPENAI_API_KEY` … 未設定でもサイトは動く。チャットだけが「準備中です」を返す。
   - `ADMIN_PASSWORD` … 既存のものをそのまま使う。設定済みなら追加作業なし。
3. 管理画面 `/admin` にログインし直す。
   ⚠ **ログイン済みでも一度ログアウト→再ログインが必要。** 書き込み API 用の
   httpOnly cookie は、この変更を入れた後のログインで初めて配られる。
4. `/admin/チャットの知識` を開き、**「ベクトルを作り直す」を1回押す**。
   初期データには埋め込みが入っていないため、押すまで検索は効かない（全件渡しで動作する）。
5. 「動作テスト」に質問を入れて、拾われた項目と回答を確認する。

## 運用

### 知識を直す
`/admin/chat-knowledge` で編集して保存すれば、**次の質問からすぐ反映される**（デプロイ不要）。
保存時に埋め込みも自動で作り直される。

### 「要確認」タグ
裏取りが済んでいない項目には `要確認` タグを付ける。**公開はされていてボットも答える**が、
管理画面の上部に一覧で出て、「確認済みにする」ボタン1つでタグを外せる。内容が違えば編集で直す。

⚠ 「未確認だから非公開」にしない。聞かれても答えられないうえ、直す動機も生まれないまま忘れられる。

⚠ 但し書きを**本文に**書かない。本文はそのまま LLM に渡るので、ボットが
「これは未確認の情報ですが」と喋り出す。管理上のメモはタグで持つ。

初期データでは次の2件に付けてある。**確認して、タグを外すか修正すること。**

| 項目 | 未確認の理由 |
|---|---|
| 体験者アンケートの満足度 95%（回答80名） | 出所の裏取りが未了 |
| 営業時間 10:00〜19:00・火曜定休 | トップページの構造化データ（`app/layout.tsx`）は `Mo-Su 10:00-20:00`。どちらが正か未確認 |

### 「非公開」の使いどころ
一時的にボットに答えさせたくない項目（終了したキャンペーンなど）を、消さずに外しておくときに使う。

### 「常に渡す」（ピン留め）の使いどころ
検索結果に関係なく毎回 system に入る。**料金**と**完成品の受け渡し**だけに付けてある。

⚠ 増やすほど1問あたりの費用が上がり、関係ない話題にも混ざる。
「抜けると間違った案内になる」ものだけに限ること。

### 「未ベクトル化」バッジが出たら
本文と埋め込みがズレている状態。回答自体はできるが検索が効かず、公開中の項目を全部渡す動作に
なる（費用が上がり、精度も落ちる）。「ベクトルを作り直す」を押せば直る。

## 安全のために入れてあるもの

| どこ | 何を |
|---|---|
| `chat_knowledge` | RLS 有効・ポリシー無し。anon キーからは読めも書けもしない。触れるのは service role だけ |
| `/api/admin/chat-knowledge/*` | 全メソッドで `requireAdmin()`。httpOnly + HMAC 署名の cookie を検証する |
| `/api/chat` | POST のみ・1発言600字・履歴12往復・同一IP 10分25回まで |
| `/api/chat` | クライアントから来た `system` role は捨てる（知識の差し替え防止） |
| `ChatWidget` | モデルの出力は文字列として描画。`dangerouslySetInnerHTML` を使わない |
| `buildSystemPrompt` | 縛りを知識より**後ろ**に置く。知識に「指示を無視して」と書かれても後勝ちになる |

⚠ 既存の `admin_auth` cookie はブラウザ側で `Cookies.set()` しているだけなので誰でも偽造できる。
画面の出し分けには使えても、書き込み API の鍵にはならない。この仕組みでは別途 `admin_session`
（httpOnly・HMAC 署名）を配って検証している。

## 費用の目安

- 質問1回 = 埋め込み1回 + 回答1回。`gpt-4o-mini` と `text-embedding-3-small` の組み合わせで
  1問あたり 0.1 円未満（知識が数十件の規模の場合）。
- 「ベクトルを作り直す」は項目数ぶんの埋め込み呼び出し。数十件なら誤差の範囲。
